# 知行读书 — 提示词中心说明文档

> 本文档说明「提示词中心」管理的全部提示词模板：它们如何驱动知识卡片、方法论、Skill 等 AI 功能的生成。
> 对应代码：`electron/services/prompt-registry.ts` + `electron/services/prompt-storage.ts` + `electron/services/template-engine.ts`

---

## 一、提示词中心是什么

提示词中心是知行读书所有 AI 功能的**提示词模板仓库**。每个 AI 功能（生成卡片、蒸馏、提取方法论等）都由一对模板驱动：

- **`{feature}.system`** — 系统人设（定义 AI 角色、输出要求、格式约束）
- **`{feature}.user`** — 用户消息模板（含 `{{变量}}` 占位符，运行时填充真实数据）

用户可在 Admin 后台或设置页编辑这些模板，**无需改代码**即可调整 AI 行为。编辑后存入 `admin_prompts` 设置项，覆盖默认模板。

## 二、模板引擎工作流

```
用户触发 AI 功能（如点"蒸馏知识卡片"）
  ↓
ai-service.ts 调 buildMessages(feature, ...)
  ↓
getPromptTemplate('ai.{feature}.system')  ← 优先读用户自定义，无则用默认
getPromptTemplate('ai.{feature}.user')    ← 同上
  ↓
renderTemplate(userTemplate, { bookTitle, highlightTexts, ... })  ← 填充变量
  ↓
组装 [{role:'system', content}, {role:'user', content}]
  ↓
调用 LLM → 返回结构化 JSON
  ↓
解析 + 落库
```

## 三、提示词清单（共 17 个模板，8 个 AI 功能）

### 1. 智能体（Agent）— 4 个

| ID | 用途 |
|----|------|
| `agent.system` | AI 学习伙伴的核心系统提示，注入 `{book_title}`/`{methodology}`/`{bloom_level}`/`{user_mastery}` 等变量 |
| `agent.intentKeywords` | 意图分类的关键词表（knowledge_query / deep_discussion / teaching_practice / casual_chat 四类） |
| `agent.difficultyHint.increase` / `.decrease` / `.mastered` | 难度升降级时的提示词片段，注入到 agent.system |
| `agent.strategy.socratic` / `.feynman` / `.assessment` | 三种教学策略（苏格拉底/费曼/评估）的提示词片段 |

### 2. 复习卡片生成 — 2 个

| ID | 用途 |
|----|------|
| `ai.generateCards.system` | 将划线笔记转化为复习卡片的人设，要求 front(问题)/back(答案)/tags 三字段，返回 JSON 数组 |
| `ai.generateCards.user` | 用户消息，变量 `{{bookTitle}}` `{{highlightTexts}}` `{{count}}` |

### 3. 全书摘要 — 2 个

| ID | 用途 |
|----|------|
| `ai.generateSummary.system` | 从划线生成结构化摘要的人设，返回 `{summary, keyPoints[]}` |
| `ai.generateSummary.user` | 变量 `{{bookTitle}}` `{{highlightTexts}}` |

### 4. 划线解读 — 2 个

| ID | 用途 |
|----|------|
| `ai.explainHighlight.system` | 单条划线的深度解读人设 |
| `ai.explainHighlight.user` | 变量 `{{bookTitle}}` `{{chapterTitle}}` `{{content}}` |

### 5. 基于笔记的对话 — 2 个

| ID | 用途 |
|----|------|
| `ai.chatWithContext.system` | 基于用户笔记回答问题的对话人设（强调引用笔记、无信息时坦诚告知） |
| `ai.chatWithContext.user` | 变量 `{{contextText}}` `{{question}}` |

### 6. 方法论提取 — 2 个

| ID | 用途 |
|----|------|
| `ai.extractMethodologies.system` | 从笔记提取可执行方法论的人设，返回 `[{name, triggerScenario, description, steps, outputFormat, examples, tags}]` |
| `ai.extractMethodologies.user` | 变量 `{{bookTitle}}` `{{highlightTexts}}` |

### 7. 书籍架构分析 — 2 个

| ID | 用途 |
|----|------|
| `ai.analyzeBookArchitecture.system` | 提炼全书核心命题、认知框架、方法论架构、知识层次的人设 |
| `ai.analyzeBookArchitecture.user` | 变量 `{{bookTitle}}` `{{highlightTexts}}` |

### 8. 知识卡片蒸馏 — 2 个

| ID | 用途 |
|----|------|
| `ai.distillKnowledgeCards.system` | 将笔记蒸馏为三类卡片（concept / methodology / quote）的人设，每卡含 title/content/interpretation/application/tags |
| `ai.distillKnowledgeCards.user` | 变量 `{{bookTitle}}` `{{highlightTexts}}` |

### 9. 知识卡片深化 — 4 个

| ID | 用途 |
|----|------|
| `ai.generateCardInterpretation.system/.user` | 为单张卡片生成「解读」字段 |
| `ai.generateCardApplication.system/.user` | 为单张卡片生成「应用场景」字段 |

### 10. Skill 生成 — 2 个

| ID | 用途 |
|----|------|
| `ai.generateSkill.system` | 将方法论转化为可安装 Skill 文件（YAML）的人设 |
| `ai.generateSkill.user` | 变量 `{{name}}` `{{nameEn}}` `{{triggerScenario}}` `{{description}}` `{{steps}}` `{{outputFormat}}` `{{examples}}` |

## 四、三大核心功能生成机制

### A. 知识卡片是怎么生成的

**入口**：书架/书籍详情页 → 点「AI 蒸馏知识卡片」

**流程**：
1. 前端调 `knowledgeCard.distill(bookId, bookTitle)` IPC
2. `knowledge-card-service.ts` 从 DB 取该书全部划线（上限 60 条）
3. 按批（默认 20 条/批）调用 `ai-service.distillKnowledgeCards()`
4. `distillKnowledgeCards` 用 `ai.distillKnowledgeCards.system` + `.user` 模板组装消息
5. 模板注入 `{{bookTitle}}` `{{highlightTexts}}`（格式化为 `[1] (章节) 内容`）
6. 调 LLM 返回 JSON 数组，每元素含 `type`/`title`/`content`/`interpretation`/`application`/`tags`
7. `extractAndParseJSON` 解析（含 `repairJSON` 兜底修复中文引号等）
8. 逐张写入 `knowledge_cards` 表，关联 `book_id` 和 `source_highlight_id`
9. 全程通过 `onDistillProgress` 事件回传进度

**关键提示词**：`ai.distillKnowledgeCards.system`（定义三类卡片和五字段输出格式）

### B. 方法论是怎么生成的

**入口**：方法论页面 → 点「提取方法论」

**流程**：
1. 前端调 `methodologies.extract(bookId)` IPC
2. `ai-service.extractMethodologies()` 从 DB 取该书划线（上限 50 条）
3. 用 `ai.extractMethodologies.system` + `.user` 模板组装消息
4. 模板注入 `{{bookTitle}}` `{{highlightTexts}}`
5. 调 LLM 返回 JSON 数组，每元素含 `name`/`nameEn`/`triggerScenario`/`description`/`steps`/`outputFormat`/`examples`/`tags`
6. 解析后写入 `methodologies` 表，关联 `book_id`
7. 方法论可被 Agent 的 `MethodologyContextBuilder` 在对话时检索注入

**关键提示词**：`ai.extractMethodologies.system`（定义方法论的七字段结构）

### C. Skill 是怎么生成的

**入口**：方法论页 → 选某方法论 → 点「生成 Skill」

**流程**：
1. 前端调 `skill.generate(methodology)` IPC
2. `ai-service.generateSkill()` 用 `ai.generateSkill.system` + `.user` 模板
3. 模板注入方法论的七个字段 `{{name}}` `{{nameEn}}` `{{triggerScenario}}` 等
4. 调 LLM 生成符合 `book-methodology-skills` 规范的 YAML 格式 Skill 文件
5. 返回 YAML 文本，前端可导出或批量导出（`skill.exportBatch`）
6. Skill 文件可安装到 Claude Code 等 AI 工具，让 AI 学会该书的某个方法论

**关键提示词**：`ai.generateSkill.system`（约束 YAML 格式和 book-methodology-skills 规范）

## 五、如何自定义提示词

### 方式一：Admin 后台
`/admin?tab=prompts` → 选模板 → 编辑 → 保存（立即生效，存入 `admin_prompts`）

### 方式二：设置页
设置 → AI 模型配置 → 提示词模板 → 编辑保存

### 恢复默认
任意模板可点「重置」恢复 `defaultTemplate`（`prompt-registry.ts` 中的初始值）

### 导入导出
支持 `exportPrompts()` / `importPrompts(json)` 批量迁移提示词配置

## 六、变量注入规则

模板中的 `{{变量名}}` 占位符由 `template-engine.ts` 的 `renderTemplate` 填充：

- 变量名严格匹配（大小写敏感）
- 未提供的变量保留原占位符（不报错）
- 支持嵌套对象展开（如 `{{user.name}}`）
- 转义：`renderTemplate` 会对变量值做安全转义，防注入

各功能的可用变量见上方「用户消息」模板的 `variables` 字段定义。
