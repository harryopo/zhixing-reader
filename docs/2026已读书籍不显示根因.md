# 2026 已读书籍不显示 — 根因定位（2026-07-24）

> 背景：用户反馈统计页「2026 已读的书籍不显示」。
> 位置在 `Stats.tsx`（Trae 正在改），按过夜约束不碰 UI 文件，只把根因和数据层结论记录供 Trae 修。

---

## 根因（两处，都在 Stats.tsx）

### Bug 1：`yearFinishedBookStats` 误用「出版年份 ≥ 2026」过滤掉书籍（最可能元凶）

`src/renderer/src/pages/Stats.tsx:652-656`：

```typescript
// 过滤 2026 年及以后出版的书籍（避免未出版/测试数据干扰年度统计）
if (b.publishDate) {
  const publishYear = new Date(b.publishDate).getFullYear()
  if (!isNaN(publishYear) && publishYear >= 2026) return false
}
```

**问题**：当前年份就是 2026。这个过滤把所有**2026 年出版的书**全部排除出年度书单。用户今年读的新书（恰好 2026 出版）会被这条规则干掉，导致「2026 已读不显示」。

原意是「避免未出版/测试数据干扰」，但阈值 `>= 2026` 在 2026 年当下等于「过滤掉今年的新书」，逻辑反了。正确做法应是 `> currentYear`（过滤未来的），而非 `>= 2026` 这种硬编码。

### Bug 2：`yearFinishedBookStats` 用 `updatedAt` 过滤当年，但「已读」完成时间未必落在 `updatedAt`

`Stats.tsx:648-651`：

```typescript
if (!b.updatedAt) return false
const t = new Date(b.updatedAt).getTime()
if (isNaN(t)) return false
if (t < startTime || t > endTime) return false
```

`updatedAt` 是「书籍记录最后更新时间」（同步进度时也会刷新），不是「读完时间」。若一本书 2025 年读完、2026 年又同步过进度，`updatedAt` 会变成 2026，反而混入；反之 2026 年读完但之后没再同步，`updatedAt` 可能还是旧值。用 `updatedAt` 近似完成时间本身不可靠。

### 数据层结论（后端无需改）

- `books` 表有 `is_finished`（0/1）和 `last_read_time`、`updated_at` 字段
- 后端 `booksDb` 无专门「按完成时间查询」接口，但 `last_read_time` 比 `updated_at` 更接近「最近阅读/读完」时间
- 真正要修的是前端过滤逻辑，数据层已能支撑

## 建议修复（交 Trae 在 Stats.tsx 改）

1. **删除 Bug 1 的出版年份过滤**，或改为 `publishYear > currentYear`（只过滤未来年份，不过滤当年）
2. **`yearFinishedBookStats` 的当年判定**：用 `last_read_time`（最近阅读时间）替代 `updatedAt`，且仅当 `is_finished === true` 时取 `last_read_time` 作为完成时间
3. `YearlyBookTable` 组件（`Stats.tsx:1562`）当前**没有年份过滤**，只过滤 `isFinished`。若要它显示「当年已读」，应复用修好的 `yearFinishedBookStats` 而非自己再 filter 一遍
